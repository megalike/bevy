# MPS patches on Bevy

This fork carries the changes Motion Pipes Studio (MPS, <https://github.com/megalike/MotionPipesStudio>) needs on top
of a Bevy release. Everything else is Bevy as released. MPS's rules for this fork: `knowledge/BEVY-FORK.md` in MPS.

## Conventions

- One branch per Bevy release: `mps/0.20.1` starts at the tag `v0.20.1`. A Bevy update starts `mps/0.21` at `v0.21.0`
  and carries over every patch below that the new release does not already contain (merged on Bevy's `main` is not
  enough).
- One change per pull request into `mps/<version>`, from a topic branch (`fix/…`, `feat/…`, `improve/…`, `perf/…`),
  squash-merged to one commit whose subject says what it is: `fix(<crate>):` a Bevy bug, `feat(<crate>):` something
  Bevy lacks, `improve(<crate>):` better quality or API, `perf(<crate>):` speed; `docs(mps):` for this file. Labels on
  the pull request say the same (`bug`, `feature`, `improvement`, `performance`) and where it may go
  (`upstream-candidate`, `mps-only`). A patch adds its row below in the same commit.
- Commit trailers, written into the squash message: `MPS-Kind` (fix / feature / improve / perf / mps-only),
  `MPS-Decision` (the MPS decision that asked for it), `MPS-Evidence` (the MPS report with the measurements). The
  upstream status (not filed / an issue or PR link / contained in a release) is kept in the table below.
- Tags mark the revisions MPS uses: `mps-<bevy version>.<n>`, for example `mps-0.20.0.1`, never moved once pushed,
  each with a GitHub release listing its patches. MPS pins exactly one tag.
- Upstream contributions are separate branches from Bevy's current `main` and follow Bevy's contribution guide and AI
  policy; the owner writes and submits them himself.

| Spot shadow cache for moving casters, decided automatically (`ShadowCacheSettings`, `classify_shadow_casters`; replaces `KeepShadowMaps`) | feature | bevy_light, bevy_pbr, bevy_render, bevy_core_pipeline | With `ShadowCacheSettings::enabled` (off by default, Bevy's behavior) every shadowed spot light is cached; nobody marks casters or lights. **Classification.** `classify_shadow_casters` (after transform propagation, bounds and asset events, before the invalidation and the lights' visibility, so the marker, the redrawn lights and the live lists agree in one extracted frame) keeps a `ShadowCasterState` on every `Mesh3d` (a required component) and a derived `StaticShadowCaster` marker (settled; shadow queries split by archetype). A caster is live again in the frame its transform (all affine bits), bounds, mesh, material, visibility or layers change by value (Bevy marks writes; `Changed` is only the candidate filter), its mesh or material asset is modified or replaced under the same id (`AssetEvent::Modified` or `Added`), or `InvalidateShadowCache::Caster` names it. While `ShadowCacheLoading` is on (the app's load gate turns it off) a caster that appears unchanged settles in the next frame; a caster spawned later, moved, or settled before settles after `settle_time` (1 s, simulation time) still, in waves (at most one per quarter of the settle time; the longest-waiting casters first while the lights they add stay within 4 besides the first caster's, so a light redraws once per wave). `SkinnedMesh`, morph weights, `VisibilityRange`, `ShadowCasterLive` (code-only override) and a material whose `Material::shadow_caching()` is `ShadowCaching::Live { max_displacement }` stay live (`LiveShadowMaterial`); `ExtendedMaterial` combines its base's and its extension's (`MaterialExtension::shadow_caching`) declarations: live if either is, the displacements added. A live material's bounds grow by the displacement: in local space along each axis by the length of the inverse transform's row (exact under shear), unbounded for a singular or nonfinite transform; in world space for the grid. The marker's hooks record the footprint a caster settled with or leaves; the lights it touches redraw. Lights follow the same rule on what projects their map (transform, angle, near plane, range, layers, map size): a changed light is drawn whole until it settles; `ShadowCacheExempt` (doc-hidden) leaves a light uncached (the audit twins). `ShadowCacheCounters` count promotions, settles, rebuild requests and the casters live, settling, waiting and forced; `SpotLightShadowCache::live_casters` per light. **Static layers.** A cached light gets a static layer of its own (a Depth32Float texture, RENDER_ATTACHMENT, TEXTURE_BINDING) within `ShadowCacheSettings::budget_bytes` (256 MiB), drawn from its settled casters only when its static revision changes (it became cached, a caster settled into or left it, the budget or map size changed, or `InvalidateShadowCache`). The budget bounds every static layer the cache holds: a layer a light gives up (it left the cache, the map size or the budget changed) counts for three more frames, until the GPU can no longer use it, and a light that would exceed the budget falls back meanwhile. **Plans.** Each frame the render world plans a cached light Kept (no views), Movers (restore the tiles of a per-light `ShadowTileMask` of 16-texel tiles that movable casters were drawn into and not restored since, plus those they touch now, then draw them), Rebuild, Restore (its shadow-map layer moved), Fallback or Dormant. A light without a usable static layer (no budget, or the restore's blit not compiled yet; `ShadowCacheLightStatus::fallback`, `SpotLightShadowCache::single_view`) is walked as an uncached light, every caster into one list for one Full view (Fallback whenever a live caster is or was in its frustum or its map is not current, else Kept); its settled casters count only for the revision, by an order-free print, and the frame it has a usable layer again finds its static list anew and rebuilds the layer. A light with a usable layer walks every movable caster in parallel (a list and a tile mask per thread, merged after; serially below 256 movers) when at least a quarter of them are near it, else only those a grid of 4 m columns (`MoversGrid`) puts near it, serially; the grid is built only while some light had few near it, rechecked every 32 frames; its settled casters are walked only until the render world acknowledged their revision. A cached light whose range reaches into no view (the frustum test clustering makes, against every active clustered camera that sees it, from a per-frame map of the lights each camera sees; `SpotLightShadowCache::lights_a_view`) finds no casters and is planned Dormant (no views): its map keeps the movers it was last drawn with, so the frame it lights a view again restores their written tiles as after any frame, with no array resize and no whole restore (`ShadowCacheState::Dormant`). Static and movable casters are split on the CPU light-frustum path and on the GPU-culled path (`RenderMeshInstanceFlags::STATIC_SHADOW_CASTER`); every spot shadow view carries a `ShadowViewKey` (light, camera, subview, `ShadowViewRole`, `ShadowMapRegion`: the texture its attachment is a view of, the layer, the rectangle), the role in the retained key's high bits; `RootNonCameraViewOrder` runs static views before movers views; the restore is a depth blit (`frag_depth` from `textureLoad`), one instanced quad per run of set tiles in a row, or one triangle over the whole layer from 7/8 of the tiles set, in one pass per light (measured: the blit against a whole-layer copy, equal on the Intel, split on the RTX; the tiles against one union rectangle per light with 1000-2000 movers over 200 x 200 m, 22-27x fewer texels, restore GPU RTX 5-8x and Intel 9-18x less, about +0.01-0.06 ms CPU). The static content counts only after its passes were recorded and every caster's mesh, material and pipeline and Bevy's GPU preprocessing pipelines were ready; the render world reports to the main world (`ShadowCacheFeedback`). `DepthStencilViewAttachment::prepare_for_new_frame` marks an aspect as unused only when it has a clear value (a `None` clear panicked). **Audit.** `ShadowCacheAuditPlugin` (a debug tool, added only on request; the example's `--oracle` uses it) gives each shadowed spot light a twin without intensity or cache (its projection and render layers kept the light's), redrawn every frame, and after the frame's passes compares the light's map and static layer with it texel by texel, in batches of 64. Every expected light-frame (each shadowed spot light the main world extracted) gets a `ShadowCacheAuditRecord` with a `ShadowCacheAuditStatus`: compared, dormant (skipped), or missing with the reason; a comparison reads the texture the views' lighting binds, only after checking from the views' keys that the light and its twin drew into it. `ShadowCacheAuditSettings` switches it at run time; `hashes` runs it without twins and hashes every shadowed spot light's map per frame, for a comparison with a run with the cache off. `ShadowCacheFaults::readiness_delay_frames` (test knob) holds a mesh's shadow pipeline back for its first frames, which makes the early-acknowledgement fault deterministic | not filed (candidate after the oracle and scale gates; the attachment fix is a bug-fix candidate) |
